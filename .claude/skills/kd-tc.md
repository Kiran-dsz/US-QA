I'll generate test cases matching the "Phase 3: Redemption — Test Cases" Notion database schema.

**Provide your source material:**
- Notion PRD link (product requirements document)
- Linear ticket URL(s) (features or bugs)
- Figma design URL (UI flows)
- Feature description or acceptance criteria

**Test case fields I'll generate:**
- **Test ID** - Auto-generated unique identifier (TC-001, TC-002, etc.)
- **Title** - Clear, outcome-focused test name
- **Main Category** - One of: Charge Correctness, Charge Recording, Code Validation, Balance Management, Error Handling, Concurrency, Analytics, Cross-Platform
- **Priotiry** - P0 (critical), P1 (important), P2 (nice-to-have)
- **Preconditions** - What must be true before the test
- **Test Steps** - Numbered sequence of actions
- **Expected Results** - Specific outcome/state/response
- **Test type** - Manual / Automated (or both)
- **Test Result** - Status tracking (Not needed, Fail, Pass, Backend, Blocked)
- **Bug Ticket** - Related Linear ticket (optional)
- **Comments** - Notes, edge cases, dependencies

**Coverage I'll provide:**
1. Happy path tests (P0) — core functionality working
2. Negative path tests (P1) — error handling, edge cases
3. Edge cases (P1/P2) — boundary conditions, concurrency
4. Backend tests — API/database validation

**How to use:**
1. Share your requirements (PRD link, tickets, designs)
2. Specify the Main Category (which area this covers)
3. I'll generate comprehensive test coverage
4. Copy the test cases into your Notion database

Start by sharing what you want to test and which Main Category it belongs to.
